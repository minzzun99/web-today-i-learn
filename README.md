## 생각해보기

###  HTML

**Q1. 나만의 갤러리에서 사진 9장은 HTML 태그 중 어떤 요소로 표현하는 것이 좋을까? 이유는 뭐라고 생각했는가?**
* `<img>` 태그를 활용해서 이미지를 나타낼 수 있습니다. 만약 설명이 필요할 경우 `<figure>` 태그 안에 `<img>` 와 `<figcaption>` 태그를 사용해서 이미지에 대한 설명을 작성할 수 있습니다. 이번 경우는 설명이 따로 필요하지 않았기 때문에 `<img>` 태그만을 사용해서 작성했습니다.

**Q2. 뼈대 코드를 기반으로 이미지를 로드하는 방식은 크게 2가지로 나뉘는데 무엇이고 어떻게 사용하고 있는가?**
* 절대 경로와 상대경로 방식이 있습니다. 
* **절대 경로**는 `https://...` 나 `C:/...` 처럼 변하지 않는 고유한 전체 주소를 지정하는 방식입니다. 주로 외부 웹 서버에 있는 이미지를 가져올 때 사용합니다.
* **상대 경로**는 `./images/gallery-1.jpg`와 같이 현재 파일의 위치를 기준으로 이미지를 찾는 방식입니다. 이번에는 Github 페이지로 배포했을 때와 로컬에서 모두 동작해야 하기 때문에 상대 경로 방식을 사용했습니다.

**Q3. 시맨틱 태그(예: `<header>`, `<main>`, `<section>`, `<footer>` 등)로 문서를 구분할 때, 어떤 기준으로 섹션을 나누고 태그를 적용하는 것이 좋을까?**
* `<nav>` : 상단의 네비게이션 바를 지정할 때 사용하는 것이 좋다고 생각합니다.
* `<main>` : 페이지의 핵심적인 내용을 담는 태그로 사용하는 것이 좋다고 생각합니다.
* `<section>` : 페이지 내부의 자기소개, 갤러리 등 독립적인 주제를 담는 태그로 사용하는 것이 좋다고 생각합니다.
* `<footer>` : 페이지의 바닥글의 태그로 사용하는 것이 좋다고 생각합니다.
* 시멘틱 태그는 페이지의 구조와 역할을 나누는 태그이기 때문에 페이지 내부의 컨텐츠가 가지는 의미에 맞게 태그를 적용하는 게 좋을 것 같습니다.

**Q4. `<img>` 태그의 `alt` 속성은 왜 필요하며, 어떻게 작성하는 것이 좋을까?**
* `alt` 속성은 이미지를 불러올 수 없을 때 이미지를 대신해서 보여주는 텍스트입니다. 스크린 리더 사용 시 이미지의 내용을 전달하기 때문에 구체적으로 작성하는 편이 좋을 것 같습니다.

**Q5. 이미지를 로드할 때, 상대 경로(relative path)와 절대 경로(absolute path)를 혼용하면 어떤 문제가 발생할 수 있을까?**
* 절대 경로와 상대 경로 두 방식을 혼용할 경우 이미지 경로가 이미지마다 달라질 수 있어서 헷갈리기 쉬울 것 같습니다. 경로를 잘못 설정할 경우 이미지가 깨질 수 있기 때문에 한 가지의 방식으로 통일하는 편이 좋을 것 같습니다.

**Q6. `<meta>` 태그의 viewport 설정과 Open Graph 태그는 각각 어떤 역할을 하는가?**
* **viewport 설정**은 모바일 환경에서도 페이지가 제대로 보이기 위해서 사용하는 태그입니다.
* **Open Graph**는 링크를 공유했을 때 나타나는 썸네일, 제목, 설명을 설정할 수 있는 태그입니다.

###  CSS

**Q1. 나만의 갤러리에서 9장의 이미지를 보기 좋게 배치하려면, Flexbox와 CSS Grid 중 어떤 것이 더 적합할까? 그 이유는?**
* **CSS Grid**가 적합합니다. Flexbox는 한 줄로 배치하는 것에 적합하고, Grid는 가로와 세로 2차원 형태의 배치에 적합하기 때문에 3x3 갤러리를 만들 때에는 CSS Grid가 적합하다고 생각합니다.

**Q2. 태그 선택자, 클래스 선택자, ID 선택자는 각각 언제 사용하는 것이 적절할까?**
* **태그 선택자** : 해당 태그 전체에 같은 스타일을 적용하고 싶을 때 사용합니다.
* **클래스 선택자** : 여러 요소에 똑같은 스타일을 반복해서 적용할 때 사용합니다.
* **ID 선택자** : 페이지 내부에서 하나의 요소에만 적용할 때 사용합니다.

**Q3. CSS를 HTML 내에 직접 작성하는 것과 별도 파일로 분리하는 것의 차이는 무엇일까?**
* HTML과 CSS를 별도로 분리해야 코드가 깔끔해지고 유지보수가 편해집니다. 또한 여러 HTML 페이지에서 똑같은 디자인을 공통으로 적용하기 쉽습니다.
* 분리하지 않을 경우 해당 HTML에서 사용한 CSS는 재사용할 수 없습니다.

###  JavaScript

**Q1. `document.getElementById()`와 `document.querySelector()`의 차이는 무엇인가?**
* `getElementById`는 ID 값으로 요소를 찾고, `querySelector`는 CSS 선택자를 활용해서 요소를 찾을 수 있습니다.

**Q2. 이벤트 리스너를 사용해서 "어떤 일이 일어났을 때 어떤 동작을 실행"하게 만들 수 있다. 자기소개 페이지에서 활용할 수 있는 이벤트에는 어떤 것들이 있을까?**
* 갤러리의 사진을 클릭했을 때 사진을 크게 보여주는 기능을 구현할 수 있습니다.

**Q3. `innerHTML`로 DOM을 조작할 때 주의해야 할 점은 무엇일까?**
* `innerHTML`로 DOM을 조작할 경우 보안에 취약합니다. 입력 폼을 통해 악성 스크립트 주입이 가능한 XSS 위험이 있어서 이 점을 주의해야 합니다.

### 배포

**Q1. GitHub Pages로 배포한 페이지에서 TIL을 작성하면, 새로고침하거나 재배포했을 때 데이터가 유지될까? 그 이유는?**

**Q2. JavaScript로 추가한 데이터를 영구적으로 저장하려면 어떤 방법이 있을까?**
